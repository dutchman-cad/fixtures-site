Alibre Design Fixture Builder

Generated script: build_alibre.ps1.

The script builds the part and assembly recipes it can express exactly, saves each as <id>.AD_PRT or <id>.AD_ASM with <id>.step (AP214) next to it, checks volume and bounding box (parts) or the solved placement (assemblies) against the answer key before saving, and writes results.json and FixtureBuilder.log. The source is builders/gen/emit_alibre.py and builders/gen/alibre_runtime.ps1; regenerate with python3 builders/gen/generate.py. Do not edit the distribution script.

Run it with Windows PowerShell 5.1 on a PC with Alibre Design installed and licensed (measured on Alibre Design Expert 28.1.1; Alibre does not have to be running):

`powershell powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\build_alibre.ps1 -OutputFolder C:\Users\Public\FixtureOut\run1 `

The output folder must not exist or must be empty; nothing existing is deleted or overwritten.

To run only some recipes, add -Only A12a,A15b (comma-separated ids): those are built, plus every design they place (the parts of an assembly), and no other row is written. Without -Only every design is built, as before.

Privacy: Alibre writes the full path of the folder it saves to into every .AD_PRT and .AD_ASM it saves (the VERSION, CONSTITUENTS, PROPDATA and STEPDATA streams, with forward slashes, in some places without the drive letter, and STEP_DATA can wrap the path across a line break). So:

  • The default output folder is C:\Users\Public\FixtureOut\alibre-<version>-<time>. An -OutputFolder must be inside C:\Users\Public\FixtureOut (a custom folder elsewhere can name a company, a drive label or a share, and Alibre writes it into every file); one inside the user profile, any user's folder under C:\Users (an 8.3 short name too), a OneDrive folder, or with the user name as a word in any part of it (FixtureOut\<name>-work) is refused before anything is written. The user name counts as a word only when it has three or more letters and is not a common word such as admin, user or owner.
  • After each design is saved and its documents are closed, every file it keeps is scanned for the private folders (the profile, Documents and Desktop wherever they are redirected, and every OneDrive folder; with or without the drive letter), any user's folder but Public, Shared, Default and All Users, the private words (user name, profile folder name, computer name, domain and logon server: as a word anywhere when five or more characters long, else inside a path), and OneDrive: the raw bytes, each stream of the compound file read through its sector table, and every zlib or raw deflate stream that inflates (a stream start is tried only when its block header and first symbols decode), as Latin-1, as UTF-16 little- and big-endian at both byte alignments and as UTF-8 (so a Cyrillic or CJK name is found too), ignoring line breaks and slash direction. A file that cannot be read, a compound file that cannot be read whole, and a compressed stream that inflates past the 8 MB scan cap all count as hits, never as clean. A hit fails that design with "privacy check" and its files are deleted (retried, read-only cleared) or, failing that, emptied.
  • At the end, every file in the run folder, listed by a row or not, is swept the same way (its name too), twice (after results.json is written and after the last log line); text files are scrubbed first. If a file with a hit cannot be removed, no zip is made and the console says to delete the folder. A run that stops early (an uncaught error or Ctrl+C) sweeps the folder the same way, makes no zip, and says "Delete this folder, do not send it" if anything could not be removed.
  • Everything printed or logged is scrubbed: a private folder or any user's folder becomes <private path> to the end of the path (the folders after it can name a person or a company), a network-share prefix becomes <network path>, a path through OneDrive becomes <private path>, and each private word becomes <name>, in backslash, JSON-escaped and forward-slash spellings. An uncaught error is printed scrubbed, never as PowerShell's own error record.
  • After every STEP export (a subassembly's too: if the rewrite fails, that STEP is removed) the header's FILE_NAME is rewritten to the bare file name, and its author and organization to empty (Alibre writes export-<id> and empty author and organization; the rewrite makes that a guarantee).
  • Alibre's API has no author, saved-by or company property (DesignProperties holds only number, description, material, density and units); the number and description are blanked before each save, and a full run on a real install leaves no match of the Windows user name in any file.
  • -PrivacySelfTest checks all of this on planted files without Alibre (refusals, scrubbing, an unlisted leftover file, an 8.3 name, the user name inside a path component, another user's Cyrillic folder in UTF-8 and in odd-aligned UTF-16, odd-aligned UTF-16 raw and inside a deflate stream, a stream past the scan cap, a broken compound file, a read-only file, a file locked against reading, the STEP header rewrite, a whole-tail user path with spaces and company folders, a network share, a relocated OneDrive, a redirected Documents folder, the computer name, a private word in a file name, UTF-16BE, the console error) and prints PASS or FAIL for each.

A failed design's error in results.json and FixtureBuilder.log ends with the innermost exception's HRESULT, the script line and its text, and the last stage the script logged (stage: lines), so a bare COMException can be placed.

It never touches an Alibre window you have open

Alibre's API (AlibreX.AutomationHook, Program\AlibreX.dll) loads Alibre's own engine into the calling process in standalone mode. The script starts that engine inside its own PowerShell process (the process id is written to FixtureBuilder.log), builds in documents it creates itself, closes only those, and ends. It does not attach to a running Alibre, does not send it any call, and does not change any Alibre option. The log ends with the number of Alibre windows before and after, which must match. A second license seat is not asked for: it ran next to an open Alibre on the same single license.

Alibre registers its COM helpers (the D-Cubed constraint solver among them) only in the manifest of its own Alibre Design.exe, so the script activates that manifest for its thread (CreateActCtx on the exe, no registry change). Without that, the first part fails with a null-reference inside the constraint solver.

What is scripted

Eighty-two designs: the first forty-six were measured on a real install (Alibre Design Expert 28.1.1) against their answer keys, and the thirty-six assembly recipes A11 to A26 were built and checked there too (builder 2026.11.24.1, 78 of the then-scripted twins ok on our test PC); the lines marked "to verify in the builder run" below changed after that run. Parts are checked against the key's volume to 1e-4 relative and bounding box to 0.01 mm where the key has them. Each part's exported STEP is then read back by the script itself, independently of the API: its declared length unit (SI_UNIT) and the box of its vertices in mm must agree with the measured box, so a unit error in the script cannot cancel out between the API's own volume and extents (builder 2026.11.23.2 and earlier wrote every part at 1/100 scale for that reason).

  • Parts (29): P01a, P01b, P02a, P02b, P03a, P03b (counterbore), P04a to P04e (constant and variable fillets), P05a to P05f (chamfers, two distances and distance-angle), P10a, P10b (sweep along a line-arc-line path), P11a, P11b (loft), P12a, P12b (user parameter and equations), P13a, P13b, P14a, P14b (sweep along a 3D sketch), P15a (part color), P16a. Lengths are centimeters in the API; the script converts from the recipes' millimeters.
  • Assemblies (53): A01a to A01e (place, ground, hide, suppress), A02a, A02b (mate), A03a, A03b (flush), A04a, A04b (angle), A05a, A05b (insert), A06a, A06b (tangent), A10a, A10b (component color), and A11a to A26b below. The key of an assembly A01 to A10 has no volume, so the script solves the constraints and then checks the resulting placement itself: the gap of a mate or flush, the angle, the common axis of an insert, the distance of the pin's axis from the face for a tangent, and the grounded, hidden, suppressed and color flags are read back. A placement check that fails makes the design failed; nothing is saved.
  • Assemblies A11 to A26 (36 of 44 twins; the other eight are in the next section). Every placement is typed: the script builds the 16-number transform itself (the part's X, Y and Z axes as rows, the translation in the last row, in centimeters) and gives it to CreateTransform, then reads WorldTransform back and compares the full 3x3 and the translation with the recipe at 1e-6 (translation in mm). After the last constraint every placed part (the children of a subassembly too, their placements carried by the subassembly's) is compared again at 1e-5 mm and 1e-6, so a constraint that moves a part, or a limit the solver does not hold, fails the design. The turn of a ring or a pin about its own axis is not compared (the key's R_scored: false).
  • A11a to A11c: the same part twice, turned 90 degrees about Z, 180 about X, 90 about Y.
  • A12a to A12c, A13a, A13b: subassemblies are built as their own files (A12-sub, A13-pair, A13-mid, each with its .AD_ASM and .step in the run folder), grounded inside, and inserted with Occurrences.Add on the .AD_ASM path; the script reads every child back through Occurrences.Item(i), with its grounding.
  • A14a to A14c: a rigid joint is a Mate of the touching faces and two flush Aligns of the side faces (the 5 mm shift of A14b is the offset of the X Align; A14c aligns the turned block's opposite faces).
  • Limits: the bounds of an offset limit (a slide) are read back from MinimumOffset/MaximumOffset exactly as given; the bounds of an Angle limit are set but cannot be read back through the API (they read empty), so an angle limit is checked by HasError and by the final orientation against the answer key. After the last constraint only A11 and up are re-checked against their placement (the answer key states it); A01 to A10 keep their per-constraint checks, since their constraints move parts. A revolved part (ring, pin) is checked for its position and where its own Z axis points, not for its spin.
  • A15a to A15c (to verify in the builder run): a turn about Z is the bottom faces Aligned, the two Z design axes Aligned, and a bounded Angle between design planes. Proven on 28.1.1: for a revolute turn about Z, an Angle value phi between the fixed part's ZX plane and the moving part's YZ plane gives the turn theta = 90 - phi, whatever the start pose, so a turn range [lo, hi] inside -90..90 is stored as [90 - hi, 90 - lo] (-45..90 becomes 0..135; A18's -90..90 becomes 0..180). A bounded Angle bounds at most a 180 degree span, so the 0..180 range of A15c is not stored: the part is built at its pose and the log says "no rotation limit stored" (the answer key's limits are skippable).
  • A16a to A16c, A17a, A17b (to verify in the builder run): a slide is an Align of two faces whose normal is the travel direction, flag unset, with bounds. The stored offset is the second proxy's face minus the first's along that normal (probed), so the script measures the offset at the recipe's pose and stores offset0 + s * (limit - travel at the pose), s = -1 when the moving part is the first proxy (as in the spec) and +1 when it is the second; the pose must lie inside, and the bounds are read back. A17 aligns the two top faces (normal +Z) and adds the Z axes Aligned.
  • A18a to A18c (to verify in the builder run): a planar motion is a Mate of the touching faces, the block's Z design axis held by a bounded Mate within -20 to 20 mm of each of the other block's YZ and XZ design planes, and a bounded Angle of -90 to 90 degrees between the two YZ planes. The limits are not made with a face Align on purpose: an Align keeps two faces parallel, so it cannot sit beside a turn limit (the probe's HasError when an offset limit and an angle limit met on one component). The script checks HasError on every constraint and fails the design, naming the constraint, if the solver rejects the combination.
  • A19a to A19c (to verify in the builder run): the API has no spherical joint. A ball is a point-to-point Mate of the pin's origin point and the assembly's origin point, with every turn left free. The pin's origin is the center of its bottom circle, which is a design point, not a vertex: if the design points are not reachable the design fails with that message. A19c is built at its pose (the pin turned 45 degrees about Y) like A19b; Alibre has no cone limit, so the 45 degree cone is not stored and the log says "no cone limit stored" (the booklet's not-a-skip case).
  • A20a to A20c (to verify in the builder run): a mirror is made without a mirror call. A20a is P04a turned 180 degrees about Y at (40, 0, 10) and A20b turned 180 degrees about X at (0, 80, 10): P04a is symmetric about z = 5, so these are the mirrors across x = 20 and y = 40, and the key scores bounding box and probes only (the booklet allows a rotated copy). A20c builds a new part P04a-mirrored in the run from P04a's own operations with every x negated (the fillet edge at x = -10), checks its volume against P04a's and places it at (40, 0, 0).
  • A23a, A23c: every placed part is already a link to its file. A23c builds the block as a part of its own (A23c-block, from P01a's ops: a file copy of P01a would carry P01a's document id and Alibre would load the unedited P01a), places it, saves, edits that part to 12 mm, saves and closes it, closes every session, opens the assembly again and reads the exported STEP (a vertex at z = 12, none at z = 10). The P01a of the run folder stays 10 mm.
  • A25a to A25d: a component is suppressed with IsSuppressed, a constraint with SuppressConstraints (read back from IsSuppressed); the pin stays where it was.
  • A26a, A26b (to verify in the builder run): a part file (A26a-block, A26b-block) is made from P01a with a second configuration Tall (the extrude depth 12 mm under a parameter transaction; the script checks the volume ratio of each configuration and that Default is unchanged). The occurrence's Configuration (found by enumerating the part's configurations) is set, the assembly saved, every session closed and the assembly opened again (the setting persists, probed), and the pin is placed and Mated after that. Each twin has its own part file (A26a-block, A26b-block), saved with the configuration the twin uses active, so the part session's geometry is the occurrence's and the Mate picks the block's top face by height. Alibre names the default configuration Config<1>: the name the script compares after the reopen is the one it resolved, not the literal Default. The final pose (pin at z = 12) and the STEP prove the height. In the session the occurrence extents and the configuration name may not follow, so the exported STEP is read (its vertex heights are in the error): its highest vertex must be 32 mm (30 for Default), with a vertex at the block's top and none at the other height. A stale geometry fails the design.

The calls used are in builders/mock/alibre_com.py (SIGNATURES), with their argument counts as read from the installed library; the tests count the arguments of every call in the script against that table.

Facts measured on Alibre Design 28.1.1:

  • The sketch axes of the ZX plane are world X and minus world Z, so P02's rectangle at z 0 to 40 is sketched at v = minus z.
  • AlibreX lengths are centimeters: Alibre's own STEP export of an API-built part declares SI_UNIT(.CENTI.,.METRE.), the SAB header's unit is 10 mm, and a 20 mm user parameter reads RawValue 2 through AlibreScript. PhysicalProperties(AD_VERY_HIGH).Volume is in cm3 and GetExtents returns the part's bounding box in cm. For a loft those extents are the control hull of the spline faces (0.37 mm too wide on P11a), so a loft's box is taken from its edges: the end points of every edge, plus the extents of circular edges.
  • Equations: a user parameter (Parameters.NewParameter, units AD_MILLIMETERS, value in mm) can drive a sketch dimension (Dimensions.PlaceLinearDimension on the rectangle side) and an extrude depth (DepthParameter.Equation) inside OpenParameterTransaction/CloseParameterTransaction; the equation evaluates to centimeters, the API unit, so the geometry follows it exactly.
  • ExportAP214 appends .stp to the name it is given; the script renames the file to <id>.step.
  • Part sessions must be reached by index (Faces.Item(i)); enumerating the collections with foreach returns objects without geometry.
  • Counterbore: AddCounterBoredHole(sketch, depth, dia, counterbore depth, counterbore dia, ...). Its through-all form fails inside Alibre with a null reference for every argument form tried, so P03b is cut to a depth equal to the part's thickness, which removes the same material (the volume matches to 1e-4).
  • Variable fillet: AddVariableRadiusFilletFeature takes two arrays, one start and one end radius per edge, the start at the edge's start vertex. The key has no volume, so the script checks the end that carries the larger radius from the center of gravity.
  • Chamfer: of AddEdgeChamferFeature(.., 0, d1, d2, ..) the first distance runs on the side face and the second on the top face; the angle form takes the distance on the side face and the angle to it. Flipped recipes swap the two legs. The key's volume is the same for both orientations.
  • Sweep and loft take sketches (2D or 3D) as paths and profiles; a path is the whole sketch, not its figures.
  • Color: IADPartSession.Color is 0xRRGGBB and reaches every feature's FaceColor. A component color is IADOccurrence.Color.
  • Assemblies: Occurrences.Add takes a saved part file, so the parts are saved first and the assembly references them in the output folder; keep the folder together. A mate with offset d puts the faces d apart (away along their normals); Align with its flag set puts a positive offset along the common outward normal. The angle argument is in radians. Alibre refuses an edge or a cylinder as a Mate target, so an Insert is a Mate of the two end faces followed by an Align of the two cylinders (the plane Mate has to come first; a cylinder Align first leaves the pin where it was). A tangent between a cylinder and a plane leaves the pin free to turn about its axis; the axis ends up parallel to the face at one radius.
  • Off to the side means 60 mm along +X; each constraint's solved placement is in results.json (placements).

What is not scripted, and why

The builder uses public calls only: AlibreX and AlibreScript. AlibreScript 6.1 (the IronPython add-on shipped with Alibre Design 28.1.1) was loaded in the builder's own process and its API enumerated: its Part class has extrude, revolve, sweep, loft, fillet, chamfer, plane, point and axis calls and its Assembly class constraints, parts and configurations, so it adds no pattern, mirror, shell or sheet-metal call. Alibre's engine has those operations internally (com.alibre.design.ops: linear, circular and mirror patterns, flanges), but neither public API reaches them.

Every other design appears in results.json as not_scripted with its reason, and the same reason is in COVERAGE.md.

  • P06a, P06b, shell: AddShellFeature builds an outward shell (outward flag set, a thickness face in the multi-thickness collector: 2728.5 mm3, exactly an outward 1.5 mm shell open at the top), but every inward form fails in the engine (VALUENEGATIVE for a positive thickness, LOPOFFBADOFFSET for a negative one, an empty multi-thickness list is refused with "Array sizes not matching"). The recipes ask for an inward shell.
  • P07a, P07b, P08a, P08b: the API has no pattern call.
  • P09a, P09b: the API has no mirror-feature call.
  • P15b: a face color cannot be set (IADFace.Color is read-only); only the part and a whole feature can be colored.
  • S01a to S13d, all 36 sheet-metal recipes: Alibre can create a sheet-metal part (CreateEmptyPartEx(name, true, ...), saved as .AD_SMP) but the API has no call that makes a base flange, edge flange, hem, corner relief or flat pattern, and an extrude in a sheet-metal part is a plain extrusion with no thickness or K-factor.
  • A07a, A07b: no component-pattern call.
  • A08a, A08b: configurations exist, but a component's suppression is not stored per configuration, whichever of the 12 configuration locks (IADConfiguration.Locks) is set on either configuration.
  • A09a, A09b: the booklet leaves A09 out for Alibre Design.
  • A21a to A21c, A22a, A22b: no component-pattern call (as A07).
  • A24a, A24b: IsFlexible sets and reads back, but nothing moves a Mated child inside a flexible instance: ApplyTransform, ApplyConstrainedTransformations and ApplyTransformations(..., true) leave it in place, ApplyTransformations(..., false) throws "Not applicable for assembly with constrained or fixed occurrences", and a temporary top-level constraint on the child is rejected by the solver (HasError).
  • A23b: no embedded copy to break the link to: every placed part is a reference to its own file, and a part made inside an assembly (AddEmptyPart) is written as its own part file beside the assembly when it is saved, so no component is ever local to the assembly.

Privacy

Before each save the part number and description are blanked. The .AD_PRT file is an OLE compound file; its VERSION stream records the folder it was saved in and two GUIDs (the volume and the document), and PROP_DATA records the save time. The STEP header has blank author and organization. Keep the CAD files private; share results only.

Native CAD files (.ADPRT, .ADASM…) carry your Windows user and computer name inside them; we keep native files private and publish only STEP and files we've checked clean.
