Download build_repro.ps1

Solid Edge repro pairs for cadmpeg

Please use a licensed copy.

build_repro.ps1 builds the small before/after Solid Edge files that the cadmpeg Solid Edge issues ask for, on your own Solid Edge (the Community Edition is fine). Each pair is the same part twice, with exactly one thing added in the second file, so cadmpeg contributors can see what that one change writes into the file. You run one command per issue.

Before you start

  1. Windows with Windows PowerShell 5.1 and Solid Edge installed (Community Edition or a licensed edition).
  2. Save your own work first. The script starts its own, separate Solid Edge, leaves any Solid Edge you already have open alone, and quits only the one it started.
  3. Leave the computer alone while it runs. It takes a few minutes.

Run it

Download build_repro.ps1, open PowerShell in the folder that holds it, and run one command per issue number:

powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\build_repro.ps1 -Issue 1871

The folder for the files is chosen with -OutputFolder. Without it, the script uses a folder called SolidEdgeRepro inside your Documents folder.

What each issue builds

  • 1863: an empty part, then a 40 x 30 x 20 mm block (stream map of a part).
  • 1865 and 1866: one block, then two bodies (a second block 60 mm along X).
  • 1867: a block from the millimeter template, then the same block from the inch template.
  • 1868: a block, then the same block with a 10 x 10 mm square cut 5 mm deep.
  • 1869: a block extruded 10 mm from a 40 x 30 mm rectangle on the Top plane, with a corner at the origin, then the same block plus a 5 mm high boss from a circle of radius 5 mm centered at (12, 7) mm. The circle is sketched on a reference plane at z = 10 mm, the height of the top face. Both sketches are used by a feature, because a sketch that no feature uses is not saved in the file. No STEP copy is made for this issue.
  • 1870: a block, then the block plus a revolved ring.
  • 1871: three pairs on the same block: a 4 mm hole through, a 2 mm fillet on an edge, a 2 mm chamfer on the same edge.
  • 1872: two pairs on a block with one small boss: the boss patterned 2 x 2, and the boss mirrored.
  • 1873: a 2 mm sheet-metal base, then the same base with a 10 mm flange.
  • 1874: an assembly with one placed part, then the same part placed twice. This also builds the part from the 1863 pair, which the assembly places.

Every pair is saved as a native file (.par, .psm or .asm) before and after, plus a matching STEP copy where the issue uses one.

Where the files go

Every run writes into a NEW folder named se-repro-<issue>-<version> inside the output folder. If that name is already taken, the script uses -2, -3 and so on. It never reuses, empties, overwrites or deletes an existing folder. In the folder you get:

  • se-<issue>-<what>-before.par and se-<issue>-<what>-after.par (.psm or .asm for issues 1873 and 1874), and the .stp copies.
  • results.json: the verdict, each kept file with its size and SHA-256, and any pair that was deleted. It holds counts only.
  • build-results.json: the measured volume, body and feature counts of each state.
  • repro.log: what happened, with the run folder name and never a full path.
  • instance.json: the Solid Edge version the run used.
  • Solid Edge's own files beside the parts: a .log per STEP export, and a .cfg per assembly (issue 1874). They are scanned like everything else.

The run ends with Result: PASS (exit code 0) or Result: FAIL (exit code 1).

Privacy: your name stays on your machine

The script reads your Windows user name, computer name, registered owner and organization, full name and profile folder on your own computer, while it runs. It uses them in memory to clean the files, and it never saves or prints them. Before it finishes it:

  1. blanks the author, last author and company fields,
  2. replaces those terms with filler everywhere in the file, and rewrites the file without its stale bytes,
  3. zeroes the unreadable 512-byte data block in each Solid Edge file (its content can't be checked, so it is overwritten with zeros of the same length and the file keeps opening),
  4. scans every file again, including the compressed parts inside it, for those terms,
  5. opens each file in Solid Edge once more, without saving, to check it is still a valid file with the same volume,
  6. scans the whole output folder one last time.

A pair that fails any step is deleted and the run reports FAIL. The output shows counts only. Files carry a fixed date (2026-01-01) instead of your save time.

Two limits. The scan knows the terms listed above and nothing else, so look at the files before you share them, and do not use your company or your own name in anything you add. And the assembly (1874) stores the location of its part: if your output folder path contains your user name, that pair is rejected, so pass a neutral folder such as -OutputFolder C:\Users\Public\SolidEdgeRepro for that issue.

Sharing

The files are yours. Share them only if you choose to, and only under CC0 (public domain), because cadmpeg tests use synthetic data or CC0 files only. Nothing in this script uploads anything.
