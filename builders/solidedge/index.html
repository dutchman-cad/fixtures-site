Solid Edge Fixture Builder

Generated script: build_solidedge.ps1.

The generated Windows PowerShell script builds native ordered parts, sheet metal and assemblies, saves native/STEP pairs, and writes results.json after every recipe. The source is builders/gen/emit_solidedge.py; regenerate with python3 builders/gen/generate.py. Do not edit the distribution script.

Use Windows PowerShell 5.1, .NET Framework 4.x, and a running Solid Edge 2026 instance in the same interactive user session:

`powershell powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\build_solidedge.ps1 -OutputFolder C:\Users\Public\FixtureOut `

The run takes about 10 minutes. A Solid Edge window may open while it runs, and that is normal. If Solid Edge is already open with your own work, the builder uses that window, so save your work first or close Solid Edge before you start. When it finishes, the script prints how many recipes were built and the zip to send to Dutchy.

Every run writes to a new folder build_solidedge-SolidEdge-<builder version> inside the parent folder you pass as -OutputFolder, or inside C:\Users\Public\FixtureOut without it (do not create the run folder yourself; the builder picks it); if that name (or its .zip) exists it takes the first free -2, -3, and so on. Nothing existing is deleted, emptied or overwritten. The full chosen path is the first line of FixtureBuilder.log, the output field of every results.json row, and the line Output folder: printed at the end next to the zip path. Only documents it creates are closed; Solid Edge stays running, and DisplayAlerts is restored. Run one builder/probe at a time.

Solid Edge stores the absolute path of every linked file inside an assembly, a drawing, or a part linked to another part, and a STEP file's header names the file it was written to (measured on Solid Edge 2026, 2026-11-25). So the builder works straight in the chosen folder only when it is under C:\Users\Public\ and no folder name in its path contains your Windows user name. Otherwise (your Documents, OneDrive, a company or drive folder, a share) it builds in C:\Users\Public\FixtureOut and copies the finished zip into the folder you chose, under the first free name. Either way, the files record only a folder that names no one. STEP headers keep the bare file name, with empty author and organization fields.

Each recipe's saved files, and any other file written while it ran, are also checked for a user folder path: a user's folder under C:\Users or under a share's Users folder, but not Public, Default, Shared or All Users, as well as a relocated profile, OneDrive or Documents folder. The check reads the bytes as text in several encodings and inflates the compressed streams inside them. A recipe whose file holds such a path, or whose file cannot be checked, is failed with a privacy: error and its files are removed. Before zipping, and also after a crash, a last pass goes over every file in the run folder. In the text logs (FixtureBuilder.log, results.json, Solid Edge's STEP translation logs), user folders become %USERPROFILE% together with the rest of their path, and your user name and computer name inside paths become <private>. Any file that still holds something private, or that cannot be read, is left out of the zip, and the recipe that wrote it is marked failed in results.json. Errors on the console are shown with the same placeholders.

To test this on a Windows computer without Solid Edge, run builders\solidedge\privacy_selftest.ps1. It loads the builder's own privacy code (and compiles its module for the byte scan), runs it on made-up files and prints one PASS or FAIL line per check.

The zip holds your native files, their STEP copies, results.json and FixtureBuilder.log, each under the run folder's name with forward-slash paths (written entry by entry: Windows PowerShell 5.1's whole-folder zip call writes backslash names, which the zip format forbids). Send that zip to Dutchy: in Discord, send Dutchy a direct message with the zip attached, or upload it on your private contributor page (/v/<your link>/builder). Files are private by default; say so if you choose to share them as CC0. Say you used the Solid Edge Fixture Builder and give your Solid Edge build. Do not post the zip in a public channel.

ok requires the numeric answer-key checks to pass before the final save. fail records a measured-versus-expected mismatch; failed records an application or lifecycle error. Both clear the result's file list and remove the builder's incomplete pair. not_scripted includes an explicit reason. Results include measured volume in mm³, exact bounds in mm, body/face/edge counts, sheet settings and flat sizes where applicable. Null answer-key values are unchecked; hints are explanatory rather than acceptance targets.

Volumes are read at the kernel's full requested accuracy (Body.ComputePhysicalProperties with accuracy 1.0). The plain Body.Volume property runs at a reduced default accuracy and is off by up to 0.2 percent on oblique curved geometry; the P14 corner sweep read 300.25 there against 299.43 at full accuracy.

Solid Edge 2026's STEP export of a part split into several bodies writes only one of them (measured on our test PC: E03a holds 42000 + 18000 mm³, its STEP held the 18000 solid; the Parasolid export has both; hiding, activating, renaming or recomputing a body, and every split option, change nothing). So when the STEP holds fewer solids than the part has bodies, each body is exported on its own (Model.SaveBody to Parasolid, re-entered through a metric part template and saved as STEP by Solid Edge) and those solids are joined into one shape representation of the one STEP file; the row says so in step_note. A body is a model with a readable body (the tool body an intersect consumed is not one).

After both files are saved and the build document is closed, each saved native file and the STEP are reopened (the STEP through an installed metric template) and compared with the pre-save measurement: volume, bounds and, for the native file, face count; a several-body part's STEP must hold one solid per body (Solid Edge re-enters it as one joined body, so the reopened STEP is only bounded by the part's volume); assemblies compare relationship counts and require at least the recorded occurrence count (a suppressed occurrence is stored in the file but not counted by the live session). A mismatch is failed and removes the pair. Results keep the reopened measurements under readback.

Acceptance uses the existing fixture tolerances: 0.01 mm for lengths and 1e-4 relative volume. It does not adjust them to observed CAD output. Sheet-rule values and flat dimensions are checked. Twins marked differs_from, and chamfer flips whose equal volumes are intentional, are checked against earlier successful native measurements using bounds, volume, face count and a vertex-coordinate fingerprint. Run those bases before their twins.

Assemblies use native ground, planar, angular, axial and tangent relationships. Their gate checks solved status, detailed status, two geometry references and occurrence owners, offsets/angles/orientation, and component/relationship counts. Suppression uses suppression variables; model states use assembly family members; view representations use configurations. Assembly files are privately saved before operations that require a named document.

Sheet-metal edge flanges (S02 and the corner pairs of S03) are built with Solid Edge's multi-edge flange command, even for one edge. On a real Solid Edge 2026 install the single-edge flange command, in ordered sheet-metal mode, makes a feature that reports failure and adds no geometry, so the builder no longer uses it. The multi-edge command takes the flange side (the upward side is the one that rises along +Z), the length, the angle, and a height-measurement choice; bend radius and neutral factor come from the part's sheet-metal rules, which the recipe sets first. The builder always passes the choice that measures the height from the outer face of the base sheet, so a height of 20 on a 2 mm sheet gives a flange top at 20 (left out, the command measures from the inner face and the top lands one sheet thickness higher, at 22); the recipes' alternative height datum is the inner-face choice. A flange that does not span the whole edge (S02f, S02g) uses the command's from-end extent types: it counts from the edge's own start or end, so the builder picks the type and the two numbers from the edge's orientation, then reads the flange's real extent back from the faces of the body and fails the recipe if it is not the requested one (measured on a real install: S02f spans x 20 to 70, S02g x 10 to 70). A flange that adds no volume, or does not grow in the requested direction, still fails its recipe. Bend deduction at 45 and 30 degrees is known to fail in Solid Edge itself (60 and 120 work, and neutral factor works at 45), so recipes that need it will report that failure honestly.

Common recipes (families S, X, E, F and D) are shared with the other programs, so their definitions live in those programs' spec files, not in builders/spec/recipes/solidedge.json. The Solid Edge selection is a capability table in builders/gen/emit_solidedge.py (COMMON_RECIPES: recipe id to the spec that defines it) with a second table (NOT_EXPRESSIBLE) of designs Solid Edge cannot make exactly, each with a plain reason that becomes the not_scripted text. The builder emits every design of a listed recipe in the order P, S, A, X, E, F, D and carries the answer keys over unchanged. The F recipes (F01, F04, F10) are the Fusion model recipes the booklet also marks for Solid Edge: F01a/F01b and the F04 holes are built as parts (measured on our test PC: F01b 7200, F04b counterbore 5671.704, F04c blind 5882.19, F04d hole up to the bottom face with Holes.AddFromTo from the top face 5803.65, F04e 118 degree drill point 5872.359; the hole data takes the drill-point angle in degrees). The F10 joints (pin bottom center on the block's top-face center, axis Z) are Solid Edge relationships between the two component part files, measured on our test PC: rigid is the planar mate of the pin bottom on the block top plus the pins' YZ and XZ base planes flush with the block's; revolute is an axial relationship from the pin's base Z axis to the block's base Z axis (the block's own coordinate system gives the axis it has no feature for) with FixedRotate off (on by default, which locks the turn) plus the mate; slider is the two flush plane pairs. Each joint is proved by moving the pin with PutTransform (Occurrence.Move and Rotate raise E_FAIL): locked directions snap back, the free one keeps the new value, and the row fails otherwise. F10d removes the block's ground, F10e hides the pin, F10f and F10g drive the slider 5 mm up and the revolute 90 degrees without adding a relationship. F10h (rigid turned 30 degrees) is not scripted: the angular relationship turns the pin to a multiple of 90 degrees whatever angle it reports.

What Solid Edge cannot express exactly, and why (every other reason from the earlier builders was tried on a real Solid Edge 2026 install and turned out to be buildable):

  • X10f (the spiral coil). The helix protrusion call with a height of zero still builds a helix as tall as pitch times turns, with a taper angle or taper ratio it adds no solid, and the spiral curve call (all three of its methods) fails with an invalid index because a new part has no reference axis to give it.
  • S09a and S09b (contour flange on an existing edge). No working call in ordered sheet metal: ContourFlanges.Add, AddEx and Add3 return E_FAIL (or a server fault with an Object[] edge set) for every extent, side, relief, edge-set form and profile plane tried on our test PC; the same profile builds as a base contour flange, so the failure is the edge-attached call. Two stacked flanges would make the shape but not a contour flange.
  • Drawings (D01 to D03, D05, D07 to D09) are made as Draft documents from the ISO Metric draft template: the model they show is built first and saved beside the drawing (F01a, F04a, F10a and the D09 part are built from the recipe text; D04a and D06a are the recipes of that name), then the sheet size, the views (base, projected, section, detail), the dimensions, the note, the parts list and balloons, the title block fields and the PDF (and DXF where the recipe asks) are made, the .dft is saved and reopened (every model a drawing shows is also saved as STEP beside its native file, the reference a reader's result is compared with; D09b saves its part's STEP again after the edit), and a drawing counts as built only when the reopened file has the recipe's sheets, view count and kinds and scales, and dimension values (read back, in millimeters). The author and company fields of the drawing say Fixture Builder; the title block gets only what the recipe gives. Confirmed on Solid Edge 2026: D01a to D01f, D01h, D02a, D03a, D08a, D08b, D09a. Not scripted yet, with its reason in results.json: D07a (the radial dimension). The ISO template draws first-angle projection, so the Top view of a Front base view sits below it and the Right view to its left. Drawing companions (D10 to D19, a standard drawing of one part each, named by id like the others: D11a.dft, .pdf, .dxf) add an isometric view at 1:2 (view orientation 9, in its own spot on the sheet) and a section cut measured from the left edge of the base view; only D11a (of D04a) is scripted, because the others dimension a hole center or an inner edge, and no way to pick those on Solid Edge is measured yet: each says which dimension in results.json. These were checked on the mock only, not on an installed Solid Edge.

How the picked and edited recipes are built (all measured on a real install, builder 2026.11.23.4):

  • Region picks (X01c, X02b, X02c, X03a to X03c, X05a, X05b, X07b) draw only the picked regions as the profile that is extruded: a picked region is a polygon or circle loop, several picked regions of one sketch are loops of one profile (several separate profiles from different profile sets extrude only the first), and picked regions that touch along an edge are drawn as one outline. A loop inside a loop (a ring) needs the closed check with nesting allowed. A construction line is made by the profile's toggle command, not by a property of the line. A second New Solid that touches nothing of the first is joined with the first extrusion collection call (the same part).
  • X04a and X04b close the profile with the model edge projected into the sketch. The profile check reports the sketch as open at that point, yet the extrusion reads it closed, so the check is called but not enforced and the volume and bounds are the gate.
  • X09a is one closed interpolation spline (order 4, close option on). X10 coils are helix protrusions: the axis start picks the climbing direction, the helix direction value picks the hand (measured: the default is right-handed), pitch, turns and height follow from the sizing type, and the axis is a line of the sketch (a construction line for X10g).
  • E01c uses the general extrusion call with two extents, E01d and E01e the from and to planes of the finite extrusion, E01f a draft treatment on the first direction (the inside side narrows).
  • E02a adds a second body first, so the overlapping extrusion stays separate; E02d does the same and then intersects the two bodies. With several bodies each body is read with its own volume, and the STEP of a several-body part re-enters as one body, so only a size bound is checked on it (the native file carries the full comparison).
  • E03a splits the solid with a plane, E03e with an extruded surface (its construction body; the same two solids, 60000 mm3, which is what its answer key says: the split method is checked in the file by hand), E03b and E03c trim it with a Boolean subtract of the plane (one side of the plane each), E03d splits the top face with the plane.
  • X11a extrudes to a curved face with the from-to call; if that call fails on the curved end face it falls back to a finite extrusion ending inside the material, which gives the same solid.
  • X12b and X12c flip one pattern direction by the reference index of the 3 by 2 pattern, and the hole centers are read back from the body.
  • S11b and S12a (unfold, optionally a cut across the flat bend, then refold): Rebends.Add takes the one flat face of the unfolded bend zone and folds the whole bend back (S11b 15428.319 mm3, S12a 14780.779 mm3, both match the recipe).
  • D01g (the note) is a rectangle balloon with the note text and a leader ending on the top edge; D03b reads the 5 mm gap with the lower end points of the two hole walls as key points; D03c adds a centerline along the hole axis with two points; D05a reads 25 mm with key points on the left edge and the hole circle; D09b re-exports its PDF from the reopened drawing (the PDF saved in the session that updated the drawing is 16 bytes). D07a stays not scripted: Dimensions.AddRadius and AddRadialDiameter raise the TabletPC inking error.
  • A09a and A09b (view representations) need a visible Solid Edge window: hidden, Configurations.Apply leaves every occurrence visible, so with Application.Visible = False they are reported as not scripted, never as built.
  • Every saved part is checked for its solid body stream (PARASOLID/STREAM0.P_B) before it counts as built, and the finish line counts recipes correctly.

Equivalent constructions the builder uses: a sketch fillet on the corner of a rectangle is built as the trimmed lines plus a tangent arc (the same sketch outline), and a three-point arc is placed by its center, start and end, counter-clockwise, whichever way it was drawn. Several closed loops in one sketch (two rectangles, or a circle inside a rectangle) and construction lines use the plain closed-profile check; a single connected chain of lines and arcs keeps the single-chain check.

Before each save, identifiable file-property fields are blanked. Native CAD files can also contain application-maintained identity data outside those properties; keeping the CAD artifacts private is part of this workflow. Errors redact local user/machine names and personal paths.

Native CAD files (.par, .asm, .psm, .dft…) carry your Windows user and computer name inside them; we keep native files private and publish only STEP and files we've checked clean.

The recording mock checks dispatch, typed arguments, acceptance and failure lifecycle. Its limited analytic geometry is independent of the answer key; other shapes are stand-ins. Mock coverage means implemented dispatch, not real CAD validation. The running real-install report is kept outside the repository by the operator. See [the API audit](solidedge-api.md) for the installed-library facts and [coverage](../COVERAGE.md) for current implementation coverage.

Unattended runs. Set FIXTURE_UNATTENDED=1 (or redirect the output) and the script prints the outcome and the next step but does not open Explorer. It attaches to the Solid Edge you started and never starts, shows or hides it.
