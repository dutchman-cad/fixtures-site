Run the Fixture Builder in Inventor

Please use a licensed copy.

For volunteers with Inventor 2016 or newer on Windows. You do not need to write code. The builder makes the supported booklet recipes with real Inventor features, then saves native files and matching STEP copies. Recipes it cannot make are listed with a reason, not silently left out.

Download and run

Save and close your own work first. Start Inventor with metric part and assembly templates available (the builder requests these explicitly and reports a failed recipe if they are missing). Allow roughly 10–30 minutes for a batch; older machines and large sets may take longer. This is an estimate, not a measured promise. Leave Inventor alone while it runs.

Choose one route. The first needs no Python, no install and no admin rights.

  • One zip (easiest): three steps.
  1. Download Inventor-builder-latest.zip (about 18 MB).
  2. Unzip it: right-click the zip and choose Extract All (do not run it from inside the zip).
  3. Double-click Run.bat in the new folder. If Inventor is not running it says "Start Inventor first, then run this again"; start Inventor and double-click Run.bat again.

It holds its own copy of Python and pywin32 and the current build_inventor.py, so nothing is installed and nothing is written outside the unzipped folder, apart from what Inventor itself writes. Your results go in the results folder next to Run.bat. When the run ends, Explorer opens with the zip selected (named Inventor-<version>-<build>.zip); that is the file to send. Windows may ask "Do you want to run this file?" for Run.bat: choose Run. (Right-click the downloaded zip, Properties, Unblock, before unzipping, avoids the question.) Delete the folder when you are done. The zip's name carries the builder version (Inventor-builder-<builder version>.zip); latest always points at the newest. It contains Python 3.12.10 and pywin32 312 unmodified; their licenses are in its LICENSES folder.

  • Inside Inventor: download build_inventor.vb and open it in a text editor. Open a new, empty metric part. Click Manage > iLogic > iLogic Browser > Rules > Add rule, name it Fixture Builder, and paste the downloaded rule text into the editor. iLogic accepts pasted rule text from any text file; .vb is the download extension. Click Save & Run. Use the builder's output-folder prompt when shown.
  • With Python: download build_inventor.py and keep the filename build_inventor.py. You need Python 3 with pywin32 installed (python -m pip install pywin32). Open Command Prompt in the folder containing the download and run python build_inventor.py. Keep Inventor open. This route writes into C:\Users\Public\FixtureOut (pass another folder as the first argument to choose a different place; a folder inside your user profile or OneDrive is refused, because files saved there carry your name inside them); the builder creates its own new folder inside it each run, so you do not create a folder by hand.

Downloads come from fixtures.dutchmancad.xyz/builders/. Use the Inventor guide and builder files there.

What happens on your machine

The builder picks its own output folder: every run makes a brand-new folder named build_inventor-Inventor-<builder version> inside the parent folder you chose (you do not create it); if that name is already taken it uses -2, -3 and so on, so an earlier batch is never reused, emptied or overwritten. The builder shows the full path when it finishes, and run.log inside the folder starts with it. It opens documents to make the fixtures, saves them, and closes the documents it created. It writes native files, .step copies, results.json, run.log, and one zip named for the Inventor version and build, all inside that new folder. Keep the matching native and STEP files together, including assembly parts.

While it runs, the builder turns Inventor's own pop-up questions off so a batch cannot sit waiting for a click, and puts your setting back when it finishes or stops. For assemblies it makes the main level of detail the active one before saving (Inventor 2016 to 2021), so Inventor does not ask for a named level of detail. run.log gets a line with the time as each recipe starts; if a batch ever looks stuck, the last START line shows which recipe it was on. When a recipe fails, a line <id> failing step <n> <operation> follows its START line, so the failing operation is named. One recipe is stopped after 4 minutes with a clear message instead of holding up the batch. Sheet metal recipes with a flange height datum, bend relief, bend transition, hem or edge-width contour flange are scripted; flange widths set by offsets need Inventor 2025 or newer and model states need Inventor 2022 or newer, and older versions report those as not_scripted with that reason. On Inventor 2016 to 2021 the builder checks what it made: a hole that removed nothing is made again the other way, a trim that kept the wrong side is redone, an offset work plane is measured and moved to the asked position, and a polyline outline Inventor refuses to extrude is retried without its dimensions. Before a recipe counts, every file it keeps is scanned for your profile path and user name (raw, ASCII and UTF-16, and inside zlib streams); a hit fails that recipe, deletes its files and says so, and results.json has the profile path replaced by %USERPROFILE%. The iLogic rule applies the same privacy rules; where the two routes still differ: the rule does not read inside zip members when it scans, and it does not build drawings (the Python builder does). The STEP header of every file is rewritten to the bare file name with "Fixture Builder" as author and organization, so a custom output folder never travels in it. Drawing recipes (D05a, D07a and the companions D11a to D18a) are built by the Python builder only (the iLogic rule says so and skips them): each one opens the model recipe it shows from the same folder (a run of just a drawing builds that model first), makes a drawing from the metric template, places the base, projected, isometric and section A-A views, adds the dimensions at the recipe's points and reads each back against the recipe's value (within 0.01 mm), fills the title block, and saves <id>.idw, <id>.pdf and <id>.dwg (Inventor DWG). The DXF is not exported on Inventor 2016: its DXF translator opens a wizard that waits for a click, so each drawing's notes says so. Two recipes stay not scripted: flange bend position (the Inventor API has no member for it) and the surface-split recipe E03e.

Open results.json in a text editor when it finishes. ok means that recipe was saved; failed includes the app's error; not_scripted explains what still needs making by hand or a newer app. Partial batches help too. A saved file still needs the portal's checks.

Assembly recipes A11 to A26 (Python route only)

The recipes with placements, subassemblies, joints, mirror, patterns, flexible subassemblies, linked parts and iParts run from build_inventor.py only; the iLogic rule reports them as not scripted ("run from the Python builder"). Subassemblies ship as their own files next to the recipe (A12-sub.iam, A13-pair.iam, A13-mid.iam, A21-pair.iam, A24-pair.iam), the iPart recipes also ship the factory and the member files in a folder of the same name (A26a-block/A26a-block-02.ipt), and the mirror and linked-part recipes ship their new part file (P04a-mirrored.ipt, A23c-P01a.ipt). A file an earlier recipe already made in the same folder is reused, never rewritten. A recipe that has to leave something out says so in the notes of its results.json row, and is still ok:

  • A18 and A19: Inventor's planar and ball joints store no limits and no position, so the limits are not stored (a note says so) and the pose is set with SetTransformWithoutConstraints and read back.
  • A14c: if the rigid joint turns the part back, it is held by one Mate and two Flush constraints instead (a note says so).
  • A20: Inventor has no assembly mirror call, so the mirror image is a new part file made from the part's own steps with one coordinate negated.
  • A23b: not scripted. Inventor keeps every placed part as a link to its own file, so there is no embedded copy to break the link to.

Every value a joint, placement, pattern or flexible move is asked for is read back; a value Inventor silently did not take fails the recipe with the numbers it read.

Running only some recipes (small machines)

On a computer with little memory, run the recipes in small batches, each in a fresh Inventor. Two optional settings, read from the environment of the process that runs the builder (Python route: set them in the Command Prompt before python build_inventor.py; they are not shown in the iLogic dialog):

  • FIXTURE_RECIPES: the recipe ids to run, separated by spaces, commas or lines (# starts a comment), or the path of a text file such as recipes.txt that holds them. Only those recipes run, in the builder's own order. An id the builder does not know stops the run before anything is built.
  • FIXTURE_SHARED_FOLDER=1: write into the output folder you give instead of making a new build_inventor-Inventor-<version> folder, so every batch lands in one place. results.json and the zip accumulate across batches; a recipe already built there (status ok, its files still present) is not built again and gets a row with status skipped_built and built_in naming the folder, while its earlier ok row stays in results.json. A recipe that failed or was not scripted is tried again. Nothing in the folder is deleted.
  • FIXTURE_UNATTENDED=1: nobody is watching (also assumed for a shared-folder batch or output that is not a console). The builder shows no message box and opens no Explorer window; the outcome and the next step go to run.log and the console. A Python run that has to start Inventor itself starts it hidden; an Inventor that is already running is never shown, hidden or otherwise touched. Default for a person: the box, and the zip selected in Explorer.

Privacy and sending the zip

Before saving, the builder blanks author, company, and related personal document properties where Inventor allows it. It keeps names, computer names, and personal paths out of its results. The portal's own privacy scan still runs; blank properties do not replace that scan. Files stay private unless you choose CC0 when uploading.

Native CAD files (.ipt, .iam, .idw…) carry your Windows user and computer name inside them; we keep native files private and publish only STEP and files we've checked clean.

Open your private contributor page on the portal, go to its bulk upload page, and choose the generated zip. Say “Inventor Fixture Builder” and give your Inventor version and build in the note. Read the receipt and any rejected-file reasons. If the page cannot accept your batch, use the link option below.

Alternatively, upload the zip to Google Drive or Dropbox and send the sharing link to Dutchy in a DM, with the same version and builder note. Keep your portal link private. Do not describe a scripted batch as made by hand or agree to a statement that does not describe your run.
